AGENT → 33JACK → CELO
One financial layer.
Many AI agents.




1
Agent requests a payment
External software submits a recipient, amount and idempotency reference to 33JACK's public preparation API.


2
33JACK validates and prepares
Input validation and a configurable preparation limit protect against malformed intents. No money is moved.


3
The authorised wallet signs
The payer reviews transaction details and independently confirms in their wallet. Agents do not receive blank-cheque access.


4
33JACK verifies proof
The API checks the successful Celo receipt and matching native-USDC Transfer event, then returns a real block explorer link.




Alpha limitations: agent identity, Self Agent ID, ERC-8004, delegated smart-account policies, persistent idempotency, and escrow are still milestones. A prepared payment is not a completed transaction.
